# MEAL Pros — تطبيق متكامل (ويب + أندرويد)

تطبيق React + TypeScript + Tailwind v4 + Vite، مع قاعدة بيانات حقيقية (Supabase)،
تسجيل دخول/حساب حقيقي، لوحة تحكم أدمن، دعم 3 لغات (عربي/إنجليزي/فرنسي)، ودعم
تحويله إلى تطبيق أندرويد حقيقي (Capacitor) بصلاحيات جهاز فعلية.

---

## 0) معاينة فورية بدون أي تثبيت

افتح **`PREVIEW.html`** مباشرة في أي متصفح (نقرة مزدوجة، بدون npm ولا خادم).
هذه معاينة تصميم ومحتوى **ثابتة** بنفس البيانات الحقيقية للمشروع (9 خدمات، 3
دورات + 3 شهادات، 6 تدريبات بقراءات مرجعية، 12 كتاب، 4 خبراء، 12 شريكاً، الأسئلة
الشائعة...)، مع نافذة تسجيل دخول تفاعلية (شكلاً فقط) لتتخيل تدفق الاستخدام.
**الأزرار فيها وهمية** (لا قاعدة بيانات) — الوظائف الحقيقية (حفظ بيانات، دفع،
دخول فعلي) تعمل فقط في المشروع البرمجي الكامل أدناه بعد إعداد Supabase.

---

## 1) التشغيل محلياً (الموقع الكامل الفعلي، بدون قاعدة بيانات بعد)

```bash
npm install
npm run dev
```

سيعمل الموقع بكل أقسامه التسويقية، لكن تسجيل الدخول/الحساب/لوحة الأدمن/التحميلات
لن تعمل حتى تُعِدّ Supabase (الخطوة التالية) — سترى تنبيهاً واضحاً في الواجهة
بدل انهيار الصفحة.

## 2) ربط قاعدة بيانات حقيقية (Supabase — مجاني)

1. أنشئ حساباً ومشروعاً جديداً على [supabase.com](https://supabase.com).
2. من **SQL Editor** داخل مشروعك، الصق محتوى الملف `supabase/schema.sql`
   بالكامل ثم اضغط **Run**. هذا ينشئ كل الجداول، صلاحيات الأمان (RLS)،
   وbucket-ين للتخزين: `resources` (عام، للملفات المجانية) و
   `paid-resources` (خاص، للكتب المدفوعة — انظر قسم "مراجعة أمنية" أدناه).
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`
4. انسخ `.env.example` إلى ملف جديد اسمه `.env` وضع القيمتين فيه.
5. أعد تشغيل `npm run dev`.

### تحويل أول مستخدم إلى أدمن
سجّل حساباً عادياً من داخل التطبيق (`/auth`) **بهذا البريد بالتحديد:
`saleh.shobail@gmail.com`**، ثم نفّذ هذا السطر مرة واحدة في SQL Editor:

```sql
update public.profiles set role = 'admin' where email = 'saleh.shobail@gmail.com';
```

بعدها ستظهر لك رابط "لوحة الأدمن" في الهيدر عند تسجيل الدخول بهذا الحساب —
ومنها تبويب "مكتبة الموارد" لرفع كتب وملفات PDF حقيقية (تُنظَّم تلقائياً في
مجلدات فرعية حسب النوع: `free_book/`، `paid_book/`... داخل مخزن Storage).

### تأكيد البريد الإلكتروني
مشاريع Supabase الجديدة تفعّل افتراضياً تأكيد البريد الإلكتروني: بعد التسجيل
سيصلك رابط تأكيد بالبريد، والتطبيق يعرض لك رسالة واضحة بذلك بدل تركك في
حالة غامضة. لتعطيل هذا أثناء التجربة السريعة: **Authentication → Providers
→ Email → Confirm email → أوقفها**.

## 3) ما الذي أصبح حقيقياً الآن (وليس تجريبياً/وهمياً)

| الميزة | كيف تعمل |
|---|---|
| تسجيل الدخول / إنشاء حساب | Supabase Auth الحقيقي (`/auth`) |
| حسابي | يعرض/يعدّل بياناتك وطلباتك من جدول `profiles` و`contact_messages` |
| التسجيل في دورة/تدريب | يُدرَج كطلب حقيقي في `contact_messages`، مرئي للأدمن |
| نموذج التواصل | يُدرَج مباشرة في قاعدة البيانات |
| شراء كتاب مدفوع | يُسجَّل كطلب حقيقي يراه الأدمن في لوحة التحكم |
| تحميل كتاب مجاني | تحميل حقيقي من Supabase Storage (bucket: `resources`) |
| لوحة الأدمن | نظرة عامة، الرسائل والطلبات، المستخدمون (ترقية/تنزيل صلاحية أدمن)، رفع كتب/موارد فعلية بملف PDF حقيقي، إدارة الدورات |

### ملاحظة مهمة عن الكتب الجاهزة في الكود
أقسام "المكتبة" و"الموارد" تعرض كتباً افتراضية مكتوبة في الكود (عناوين ووصف
حقيقي)، لكن أزرار تحميلها تشير إلى ملفات باسم `free-book-1.pdf`، `free-book-2.pdf`...
و`guide-1.pdf`, `guide-2.pdf`... داخل bucket **`resources`** (العام).
**ارفع ملفات PDF فعلية بهذه الأسماء بالضبط** (من Supabase Dashboard →
Storage → resources، أو عبر لوحة الأدمن) ليعمل التحميل. أي كتاب تضيفه
لاحقاً من لوحة الأدمن ("مكتبة الموارد") يعمل تحميله تلقائياً بدون أي تسمية
خاصة — يظهر مباشرة في صفحة "المكتبة" بشارة "أُضيف حديثاً"، وكذلك أي دورة
تضيفها من تبويب "الدورات" في لوحة الأدمن تظهر فوراً في قسم "الدورات
التدريبية" بالصفحة الرئيسية.

### قراءات مرجعية حقيقية
كل دورة/تدريب في قسمي "الدورات" و"التدريبات" يحتوي زر "قراءات مرجعية
موصى بها" يعرض كتباً حقيقية منشورة فعلاً (المؤلف والناشر وسنة النشر) من
`src/data/referenceBooks.ts` — عناوين ببليوغرافية فقط (بدون إعادة نشر
محتواها، احتراماً لحقوق النشر)، للرجوع إليها من مكتبتك أو الناشر.

## 4) مراجعة أمنية — 3 ثغرات حقيقية تم اكتشافها وإصلاحها

راجعت الصلاحيات (RLS) بعمق وأصلحت ثلاث مشاكل حقيقية قبل تسليم النسخة:

1. **تصعيد صلاحيات (الأخطر):** سياسة "المستخدم يعدّل ملفه الشخصي" كانت
   تسمح بتعديل أي عمود، بما فيه `role` — أي أن أي مستخدم مسجّل كان يقدر
   يرقّي نفسه لأدمن مباشرة من console المتصفح بدون المرور بالواجهة. أضفت
   trigger في قاعدة البيانات (`lock_sensitive_profile_columns`) يمنع أي
   شخص غير أدمن من تغيير `role` أو `email` الخاصين به، مع بقاء تعديل
   الاسم/الهاتف يعمل بشكل طبيعي.
2. **تسريب ملفات مدفوعة محتمل:** كل الملفات (مجانية ومدفوعة) كانت
   ستُخزَّن في نفس bucket العام `resources` — أي رابط لملف كتاب مدفوع
   كان سيصبح قابلاً للتحميل من أي شخص بدون دفع. فصلت التخزين إلى bucket
   عام `resources` وbucket خاص `paid-resources` (لا يقدر أحد غير الأدمن
   يقرأه)، ولوحة الأدمن ترفع كل ملف للمكان الصحيح تلقائياً حسب نوعه.
3. **خلل وظيفي:** صفحة "حسابي ← طلباتي" كانت ستظهر فارغة دائماً حتى لو
   عندك طلبات فعلية، لأن جدول `contact_messages` ما كان فيه سياسة SELECT
   تسمح للمستخدم برؤية طلباته هو (فقط الأدمن كان يقدر يقرأ الجدول).
   أضفت سياسة "users can view their own messages".

> إذا كنت شغّلت `supabase/schema.sql` قبل هذا التحديث، أعد لصق وتشغيل
> النسخة الجديدة كاملة — كل الأوامر فيها `if not exists` / `drop ... if
> exists` فتعمل بأمان حتى لو شغّلتها أكثر من مرة، ولن تحذف بياناتك
> الحالية.

## 5) الصلاحيات (Permissions) والتطبيق الأصلي (Android)

موقع الويب وحده **لا يمكنه أبداً** الحصول على صلاحيات مثل جهات الاتصال أو
حالة الهاتف — هذه صلاحيات نظام تشغيل تخص تطبيقات الأندرويد الحقيقية فقط.
لذلك تم تجهيز المشروع بـ **Capacitor** الذي يحوّل نفس كود React هذا إلى تطبيق
أندرويد مثبَّت فعلياً:

```bash
npm install
npx cap add android      # يولّد مجلد android/ (يحتاج إنترنت، مرة واحدة فقط)
npm run cap:sync         # يبني الموقع وينسخه للمشروع الأصلي
npm run cap:open:android # يفتح المشروع في Android Studio
```

بعد `npx cap add android`، افتح
`android/app/src/main/AndroidManifest.xml` والصق فيه محتوى
`android-manifest-permissions.xml` (الموجود بجذر المشروع). كل صلاحية هناك
مربوطة فعلياً بكود شغّال في `src/lib/device.ts`:

- **CAMERA** → `takePhoto()` (يعمل أيضاً كموقع ويب عبر كاميرا المتصفح)
- **READ/WRITE_EXTERNAL_STORAGE** → `downloadFile()` (تحميل الملفات، Downloads)
- **READ/WRITE_CONTACTS** → `pickContacts()`
- **READ_PHONE_STATE** → `getDeviceInfo()`
- **INTERNET / ACCESS_NETWORK_STATE** → `getNetworkStatus()`

> ⚠️ **قبل نشره على Google Play:** لا توجد حالياً أي ميزة في التطبيق تستخدم
> فعلياً جهات الاتصال أو حالة الهاتف. جوجل بلاي يصنّف هاتين الصلاحيتين ضمن
> "الصلاحيات المقيّدة" ويطلب تبريراً بميزة واضحة داخل التطبيق، وغالباً يرفض
> التطبيقات التي تطلبهما بدون سبب واضح. التفاصيل والتوصية الكاملة موجودة
> كتعليق أعلى ملف `android-manifest-permissions.xml` — إمّا أضف ميزة حقيقية
> تستخدمهما (مثل "دعوة صديق من جهات الاتصال")، أو احذف السطرين قبل النشر؛
> باقي التطبيق يعمل بشكل طبيعي تماماً بدونهما.

التطبيق يعمل أيضاً كـ **PWA** (قابل للتثبيت من المتصفح على الشاشة الرئيسية)
بدون الحاجة لـ Android Studio إطلاقاً — عبر `public/manifest.webmanifest`.

## 6) تعدد اللغات (عربي / إنجليزي / فرنسي وقابل للتوسّع)

اللغة تُدار مركزياً في `src/context/LanguageContext.tsx`. الهيدر وصفحات
تسجيل الدخول/الحساب مترجمة بالكامل للغات الثلاث. أقسام الصفحة الرئيسية
التسويقية (الخدمات، الدورات، الفريق...) تدعم عربي/إنجليزي حالياً وتتراجع
تلقائياً للعربية إن اخترت الفرنسية، لأنها موروثة من تصميم Figma الأصلي.
لإضافة الفرنسية (أو أي لغة أخرى) لأي قسم منها: افتح الملف وأضف مفتاحاً
`fr: { ... }` بنفس شكل `ar`/`en` بالضبط داخل كائن `content` — لا حاجة لأي
تغيير آخر.

## 7) هيكلة المشروع

```
src/
  components/       أقسام الموقع + مكوّنات ui (shadcn) + DownloadButton
                     + SaveOfflineButton + BiometricGate + BackButtonHandler
  context/          AuthContext (Supabase) و LanguageContext
  data/             referenceBooks.ts (المراجع الحقيقية)
  lib/              supabaseClient, device (كاميرا/جهات اتصال/GPS/تحميل)،
                     notifications (إشعارات محلية)، biometric (بصمة/Face ID)،
                     offlineLibrary (حفظ بلا اتصال)، requests, utils
  pages/            HomePage, AuthPage, AccountPage, AdminPage, MyLibraryPage
supabase/schema.sql الجداول + الأمان (RLS) + bucket التخزين + عمودا الموقع/المرفق
android-manifest-permissions.xml  مقتطف صلاحيات أندرويد الجاهز للّصق
ios-info-plist-permissions.xml    مقتطف صلاحيات iOS الجاهز للّصق
capacitor.config.ts إعداد التطبيق الأصلي (لوحة مفاتيح، شاشة بدء)
MOBILE_BUILD_GUIDE.md دليل التحويل لأندرويد/iOS + شرح الميزات الخمس بالتفصيل
```

## 8) التحقق النهائي — ماذا اختبرت فعلياً، وماذا يتبقى عندك

هذا المشروع (الكود المصدري في `src/`) كُتب داخل بيئة **بلا اتصال إنترنت**، لذلك
لم يكن ممكناً تشغيل `npm install` هنا (يحتاج تنزيل ~35 حزمة الآن بعد إضافة
إضافات Capacitor للإشعارات والموقع والبصمة) ولا تشغيل خادم Vite حي — قيد في
بيئة التنفيذ نفسها وليس بالكود. بدل التظاهر بالتحقق، هذا بالضبط ما فعلته:


**على الكود المصدري الحقيقي (`src/`, 37 ملف TS/TSX):**
- فحص آلي لتوازن الأقواس `{}()[]` وصحة كل مسار استيراد (نسبي وحزمة خارجية)
  في كل ملف — أُعيد بعد كل دفعة تعديلات.
- اكتشفت وأصلحت أخطاء برمجية حقيقية كانت ستُكسر التطبيق أو تُنتج سلوكاً
  خاطئاً بصمت: توجيه (`navigate`) أثناء الـ render بدل `useEffect`، استخدام
  `React.FormEvent` بدون استيراد `React`، ومهمّ أكثر — **8 استدعاءات لقاعدة
  البيانات بلا معالجة أخطاء** (`.then()` بدون `.catch()`) كانت ستُسبب دورانَ
  تحميل لا نهائي في لوحة الأدمن وصفحة الحساب إذا تعطّل الاتصال بـ Supabase،
  بدل عرض حالة فارغة نظيفة. كلها مُصلحة الآن.
- راجعت سياسات RLS في `supabase/schema.sql` يدوياً وأغلقت ثغرة تصعيد صلاحيات
  حقيقية (أي مستخدم كان يقدر يرقّي نفسه لأدمن عبر استدعاء تحديث مباشر) وثغرة
  انتحال هوية في نموذج التواصل.

**على `PREVIEW.html` تحديداً — شغّلته فعلياً وليس نظرياً:**
باستخدام Playwright (متصفح Chromium حقيقي متوفر في بيئتي)، فتحت الملف فعلياً،
تابعت أخطاء الـ console، ونقّلت الفحص عبر الصفحة كاملة (البطل، الدورات،
التدريبات، الفريق، الشركاء) وفعّلت نافذة تسجيل الدخول وأكورديون الأسئلة
الشائعة — التقطت لقطات شاشة حقيقية من كل خطوة. الخطأ الوحيد الذي ظهر هو فشل
403 لتحميل خط Google Fonts، وهو متوقع تماماً بسبب عدم توفر إنترنت هنا (الخط
يتراجع لخط النظام تلقائياً)، وليس خطأً في كود الصفحة.

**ما يتبقى عندك فعلاً (يحتاج إنترنت حقيقي لا أملكه هنا):**
```bash
npm install && npm run dev
```
ثم افتح `http://localhost:5173`. هذه الخطوة الوحيدة المتبقية للتحقق من أن
حزم npm نفسها (الإصدارات المطلوبة في `package.json`) تتوافق مع بعضها فعلياً
عبر مُجمِّع Vite — وهو تحقق لا بديل عنه سوى تشغيله على جهاز متصل بالإنترنت.
إذا ظهر أي خطأ عندك، الصقه هنا وأصلحه فوراً. إذا لم يكن لديك Node.js مثبّت،
أو تفضّل ألا تفتح طرفية (terminal) بنفسك، تطبيق **Claude Code** يقدر يفتح
المشروع، يشغّل هذين الأمرين، ويعرض لك المعاينة والأخطاء مباشرة لحظة بلحظة.
